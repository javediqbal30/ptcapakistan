# PTCA Website

Official website for **Prime Tax & Corporate Academy (PTCA)**, Karachi, Pakistan.

Built with [Astro 5](https://astro.build) for a zero-JavaScript-by-default architecture that
ships fully rendered HTML — the format both search crawlers and generative engines
(ChatGPT, Gemini, Perplexity, Copilot) read best.

## Commands

| Command           | Action                                              |
| ----------------- | --------------------------------------------------- |
| `npm install`     | Install dependencies                                |
| `npm run dev`     | Start dev server at `localhost:4321`                |
| `npm run build`   | Production build to `dist/`                         |
| `npm run preview` | Preview the production build locally                |
| `npm run check`   | TypeScript / Astro diagnostics                      |
| `npm run assets`  | Regenerate PNG brand assets from the SVG sources    |

## Brand assets

`public/ptcalogo.jpeg` is the **master artwork** supplied by PTCA (1600×1600
canvas, artwork occupying the centred 1054×1111). It is used directly by the
header, footer and About page via the `<Logo>` component.

Because the master carries a wide white border, `<Logo source="master">` renders
it inside a small `overflow: hidden` frame and offsets the image on both axes, so
the visible logo is exactly the artwork at the requested height — no 34% empty
space, no distortion.

```astro
<Logo size={54} />                  <!-- /ptcalogo.jpeg, cropped to artwork -->
<Logo size={64} source="full" />    <!-- /logo.png, pre-trimmed to 320px -->
<Logo size={32} source="mark" />    <!-- crest only, for favicons -->
```

The pre-rendered PNGs (generated by `npm run assets`) are used wherever a tight
file matters: favicons, iOS icon, Open Graph card and schema.org.

| Output                       | Used for |
| ---------------------------- | -------- |
| `logo.png` (320px, 48 KB)    | schema.org `logo`, large placements |
| `logo-mark.png` (320px)      | favicons |
| `favicon-32.png` (32px)      | browser tab |
| `apple-touch-icon.png` (180px) | iOS home screen |
| `og-default.png` (1200×630)  | link previews (WhatsApp/FB/X) |

Regenerate the PNGs with `npm run assets`. The script trims the white border and
isolates the crest by detecting brand-green pixels (the wreath is green, every
wordmark is black), so it stays correct if the master is re-exported.

Colours match the artwork: brand green `#22A74A` (`--brand-500`), globe grey `#8C8C8C`.

```text
src/
├── components/
│   ├── forms/       EnrollForm, ContactForm
│   ├── layout/      Header, Footer, MobileBar, WhatsAppFloat
│   └── ui/          Icon, Logo, CourseCard, MentorCard, Accordion,
│                    Breadcrumbs, SectionHead, CtaBanner

│   ├── courses/     6 course markdown files (frontmatter = source of truth)
│   ├── mentors/     Mentor profiles
│   └── posts/       Knowledge-hub articles
├── data/            site.ts (NAP), navigation.ts, formOptions.ts
├── layouts/         BaseLayout, LegalLayout
├── lib/             seo.ts, schema.ts, content.ts
├── pages/           Routes, incl. robots.txt.ts and llms.txt.ts
└── styles/          tokens → base → components → forms → layout → sections → footer
```

## Key conventions

- **Design tokens only.** No hard-coded colours, font sizes or spacing in components —
  everything comes from `src/styles/tokens.css`.
- **Content is data.** Course/mentor/article frontmatter is validated by Zod at build time,
  so a malformed file fails the build instead of shipping broken UI or invalid schema.
- **SEO is centralised.** Pages pass `{ title, description, canonical }`; `BaseLayout` handles
  title suffixing, Open Graph, Twitter cards and canonical tags.
- **Structured data is generated, not hand-written.** `src/lib/schema.ts` builds a single
  `@graph` per page (Organization, WebSite, Course, Person, Article, Breadcrumb, FAQ).
- **Single source of truth for contact data.** Phone, email and address live only in
  `src/data/site.ts` and flow into the UI, footer, schema, `robots.txt` and `llms.txt`.

## Enrolment form

Course pages link to `/enroll/?course=<slug>`, which pre-selects the course. The form is
three steps and collects the required fields: name, mobile/WhatsApp, email, course,
learning mode, city, education and professional status, plus consent.

Submit behaviour is configurable:

```bash
PUBLIC_ENROLL_ENDPOINT=https://your-form-endpoint   # POST FormData here
PUBLIC_CONTACT_ENDPOINT=https://your-form-endpoint   # contact page form
```

If no endpoint is set, submissions fall back to opening WhatsApp with the collected
details pre-filled, so no lead is ever lost before a backend exists.
